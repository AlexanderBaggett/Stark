# Phase 1 - Language Feature Gap Analysis

Severity meanings:

- `blocker`: port cannot be kept faithful without this feature or a deliberate
  whole-port rewrite convention.
- `workaround-exists`: the compiler can be ported with more verbose Stark.
- `nice-to-have`: improves maintainability but does not block self-hosting.

Design states:

- `specified`: documented language contract exists.
- `partially implemented`: grammar/compiler support exists but is incomplete for
  self-hosting use.
- `unspecified`: no settled Stark surface or port convention found.

## Gap Table

| ID | Feature / Capability | Host Compiler Use | Severity | Design State | Audit Finding |

| L01 | Error-value propagation for `Result` / `Option` style code | Host uses `throw`, `try`, `catch`, nullable returns, and `InvalidOperationException` in `src/Compiler/CompilerPipeline.cs`, `src/Compiler/NativeToolchain.cs`, `src/Compiler/CompilerCli.cs`, parser helpers, package loading | blocker | **implemented (v2)** | **Closed (v2, doc `11`):** `try expr` (visible leading-keyword early return, statement-boundary positions) unwraps the `[Ok]` variant and propagates the `[Err]` variant of any **two-variant enum carrying `[Ok]`/`[Err]` role attributes** — structural, no privileged stdlib types, no name matching; differing error payloads convert through the enclosing error type's `from` funnel (declared once on the error enum), and a missing funnel is a compile error. Stdlib result/status enums are annotated; cross-family propagation (e.g. stdlib `IOResult` operand inside a user result-returning function) works through funnels; role/misuse diagnostics STK3037–STK3043; runtime + diagnostics tests and user-facing docs cover the role model. Cross-module package-image carry of roles/funnels remains open as EP15. |
| L02 | Pattern binding in branch conditions (`if let`, `while let`) | C# relies on `is { } value`, nullable pattern checks, `switch` expressions, and guard-heavy branching throughout `TypeChecking.cs`, `SemanticValidation.cs`, package loaders | workaround-exists | **implemented** | **Closed by `is`-pattern conditions:** `if (expr is pattern)` and `while behavior (expr is pattern)` reuse the `switch case` pattern grammar/binder verbatim — full enum/nested/struct/named-field/`var`/`_`/literal coverage — binding captures into the consequent (then-branch / loop body). Lowers to the same discriminant-test-and-bind machinery as a single-case `switch` (no extra cost), with identical move-out-of-scrutinee and drop semantics. Maps the host's `x is Foo f` directly. |
| L03 | Explicit traversal loops | Host uses `foreach`, LINQ, `IEnumerable<T>`, `yield return` in passes and helpers such as `CompilerPipeline.cs`, `ParameterMemoryContractFacts.cs`, `NativeToolchain.cs` | workaround-exists | **implemented** | **Closed (doc `08`):** Stark now supports exactly three explicit `for ... in ...` traversal loop forms before self-hosting: borrowed element traversal, mutable borrowed element traversal, and indexed borrowed traversal. The implementation supports fixed arrays, slices, and dynamic storage, lowering to counted loops over existing element-address operations with no iterator objects, `yield`, hidden allocation, LINQ-style API, or runtime dispatch. Collection APIs still need fast explicit count/index/slice access for hot compiler paths and for cases outside the three forms. |
| L04 | Rich switch patterns: or-patterns, range patterns, list patterns, property patterns | C# source uses switch/pattern matching heavily in validators, lowering, text rendering, package codecs, and generated parser interaction | workaround-exists | **implemented** | Stark supports literal, discard, `var`, enum case, generic enum case, named-field enum, aggregate patterns, switch-label or-pattern alternatives (`case A \| B:`), inclusive integer range patterns (`case 0..10:`), aggregate property patterns (`case Box { Field: pattern }:`), and exact-length list patterns over fixed arrays/slices/dynamic storage (`case [first, second]:`). Or-pattern alternatives that bind captures must bind the same names with the same types, or the section is a compile-time error. Range patterns use interval coverage and lower without case expansion. Property patterns require every aggregate field exactly once. List patterns are exact-length; fixed-array length mismatches are compile-time errors, while slice/dynamic list patterns lower to a length check plus direct element tests. Typed package-image templates preserve range, property, and list pattern facts across module boundaries. |
| L05 | Generic value parameters / const generics | Host models fixed arrays, bounded raw pointers, target/layout facts, and template bodies; stdlib and tests would benefit from generic fixed-size helpers | workaround-exists | **implemented (integer slice)** | **Decision closed (OQ-22, docs `08` and `13`):** add typed `comptime` generic value parameters as Stark's const-generic spelling, e.g. `struct FixedBuffer<T, comptime u64[0 max] N>`. The self-hosting range-typed integer slice has landed: parser support, typed signature/named-type metadata, symbolic fixed-array lengths (`T[N]`), fixed-array argument inference, range diagnostics, explicit integer value arguments at type/function call sites (`Length<i32[min max], 3>(values)`), symbolic forwarding with `comptime N`, function monomorphization keys, scalar body materialization (`return N`), type-reference package-image preservation for symbolic lengths, imported-template value substitution, and full package/source-surface metadata for comptime parameter declarations. Non-integer comptime value kinds are deferred until a concrete compiler or stdlib use case needs them. |
| L06 | General operator/hash/equality doctrine surface for generic algorithms | Host relies on .NET string equality, `StringComparer`, generic hashing, numeric operators, comparison/sort helpers, dictionaries/sets throughout `TypeChecking.cs`, `ProjectCliDriver.cs`, package builders/loaders | blocker | partially implemented | **Design closed by OQ-08 and doc `19`:** generic collections and algorithms use explicit `Hash` + `Eq`, `Ord`, and `Format` contracts as the public language/stdlib model; the compiler uses strongly typed interned IDs as its hot-path representation. Traits are implemented (see `10-traits-and-dynamic-dispatch.md`): impl via base list, `Self`, conformance, default members, associated types, and `where T: Trait` constrained generics, all statically dispatched to direct calls. Landed: canonical contract names and explicit static `Dictionary<K,V>` key `Hash`/`Equals` support for non-primitive key types. Remaining work is stdlib/collections coverage: text key contracts, `HashSet<T>`, ordered/deterministic collection paths, borrowed lookups, typed compiler interners, and missing-contract diagnostics. |
| L07 | Compiler invariant failure policy (`panic` / `trap` / abort) | Host throws for impossible states: missing artifacts in `CompilerPipeline.cs`, unsupported accepted bodies in LLVM/MIR paths, toolchain failures in `NativeToolchain.cs` | blocker | **closed (no new surface)** | **Resolved without adding panic/trap/assert (OQ-05, doc `09` Error Model):** invalid states are made unrepresentable instead. Switch exhaustiveness (STK3044) and definite-return analysis (STK3045) turn unmatched-value and fall-off-the-end paths into compile errors; toolchain/environment failures port as `Result` + `try`; the residual self-detected-bug category reports via `Result<T, InternalError>` or stderr + `System.Process.Exit(1)`. Port convention documented in doc `09`. |
| L08 | Raw/multiline/interpolated string literal ergonomics for compiler text | Host builds LLVM IR, diagnostics, source snippets, JSON, and long test source strings with C# raw/interpolated strings and `StringBuilder` | workaround-exists | **implemented (language literal slice)** | **Closed for source literals:** `Stark.g4` accepts exact-preserving `raw"..."` and multiline `raw"""..."""` as ordinary `StringLiteral` tokens, and `$raw"..."` / `$raw"""..."""` compose with existing interpolation. Escapes are not interpreted inside raw literals; multiline content is preserved exactly between delimiters. Remaining text-builder and escaping APIs are stdlib gap S02/S03, not a source-literal syntax gap. |
| L09 | General compile-time function evaluation and program-structure branching | Host uses `CompileTimeExpressionEvaluator.cs`, `IntegerRangeStorageFacts.cs`, enum layout, SSA const lookup-table folding, text/path specializers, typed package facts, ABI/layout facts, trait/doctrine facts, and compiler metadata builders | workaround-exists | specified; implementation open | **Decision closed (doc `13`):** `comptime` scope is CTFE plus broad compile-time branching over explicit program-structure facts. Stark must evaluate ordinary compile-time code for constants, tables, range/layout facts, and compiler metadata, and must allow compile-time branches over types, fields, enum variants, functions, attributes, doctrine/trait conformance, associated types, ABI/layout facts, and package metadata. Structural facts are compile-time-only and erase before backend lowering; no runtime reflection is introduced by this feature. |
| L10 | Async/build-driver concurrency replacement | `src/Compiler/ProjectCliDriver.cs` and `src/Compiler/CompilerCli.cs` expose `async Task<int>` and use async stream/process APIs | workaround-exists | **closed as porting convention** | The host compiler is functionally single-threaded: zero parallelism (`Task.WhenAll`/`Parallel`/threads — none); every `await` is sequential I/O (console/file writes, process wait). A synchronous Stark port is behaviorally identical, so self-hosting does not need `async`/`await`. OQ-11 resolves future parallel build/test coordination as a narrow stdlib scope in doc `22`: captured thread payloads, `System.Threading.Synchronized<T>` / `Locked<T>`, and MPSC channels. |
| L11 | Nullability and optional-value conventions | Host nullable references (`string?`, `Type?`, `TryGet(... out T?)`) are pervasive in type/model queries | blocker | **closed (convention specified; stdlib type implemented)** | Safe Stark has no nullable safe references; raw `null` is only for raw pointers and FFI. The blessed porting convention is `System.Option<T>` with `[Ok] Some(T)` / `[Err] None`. C# nullable returns, nullable fields, and `TryGet(... out T?)` become `Option<T>` values; callers inspect them with `switch` / `is Option<T>.Some(var value)` or propagate absence with `try` when the enclosing return type is also option-shaped. Project-local option-shaped enums remain legal under the structural `[Ok]`/`[Err]` role model, but `System.Option<T>` is the default self-hosting pattern. |
| L12 | Partial/nested/generated type layout ergonomics | Host uses generated partial parser classes, nested parse contexts, nested helper classes, nested records, and partial lowering/emitter classes | workaround-exists | partially implemented | Stark supports modules and top-level data declarations, but no evidence of partial type declarations or nested named types. The self-hosted parser will not port generated ANTLR parse-context classes; the handwritten parser should expose a Stark-native token/tree facade, while other nested helper shapes can be flattened into modules or explicit records. |
| L13 | Alias/noalias proof carriers and wrong-alias diagnostics | Host tracks `ScopedNoAliasGroup`, memory contracts, root keys, `if disjoint(...)`, `unsafe assume disjoint(...)`, and validates call-site disjointness in `TypeChecking.cs` before LLVM emission | blocker | specified; implementation open | **Decision closed (OQ-17, doc `09`):** APIs that need alias facts use explicit compile-time-only proof carriers, those carriers erase before codegen, and wrong proof use is rejected during type/lowering/SSA validation. `unsafe assume disjoint(...)` remains the only way to introduce an external disjointness fact, and it must perform explicit root checks. Self-hosting still must implement the proof-carrier artifact model, package-image preservation, validation, and diagnostics. |
| L14 | Parser generator/runtime strategy | Host parser is ANTLR-generated C# from `Stark.g4`, with runtime dependency and generated parse-context classes | blocker | **specified (handwritten parser)** | **Decision closed:** `Stark.g4` remains the canonical grammar reference, but the self-hosted compiler will use a handwritten parser rather than porting ANTLR runtime/generated code. Parser conformance tests should compare the handwritten parser against the canonical grammar and, while the host exists, the current C# ANTLR parser as an oracle. Tracked in tooling as T01. |

## Features Verified Present Enough For Porting

| Feature | Evidence | Remaining Caveat |
|---|---|---|
| `struct`, `record`, `enum` | `Stark.g4`, `docs/Userfacing/LanguageReference.md` sections 8.1-8.4 | Porting records/classes still needs ownership/storage choices |
| Generic type parameters | `Stark.g4` `typeParameterList`, Language Reference 6.5 | Type-only generics, no const/value parameters |
| Function kinds | Grammar supports `fn`, `finite`, `law`, `finite law`; pipeline derives function effects | Port must preserve effect-refinement artifacts |
| Function pointers and closures | Language Reference 5.5-5.7 | Heap closure support and shared capture need careful stdlib/runtime review |
| Type aliases | Grammar `alias`, `TypeAliasSymbol`, `StarkTypeResolver` | Type aliases do not create distinct runtime alias classes |
| Borrow classes | `borrow`, `retborrow`, `storeborrow`, `frozen`, `shared`, `const` in grammar/docs | Port must avoid using C# shared references as a design crutch |
| Dynamic storage | Language Reference 6.4; stdlib uses `dynamic T` | Collection surfaces still need self-host compiler-grade APIs |
| Memory contracts | `where disjoint`, `where overlap`, `where same`, `if disjoint`, `unsafe assume disjoint` in grammar/docs/source | Alias proof carriers are the chosen first-class compile-time artifact and still need implementation |
| Unsafe/FFI/asm | Grammar and stdlib platform modules | Self-host compiler should keep unsafe boundaries small and auditable |
| Loop behavior | `infinite`, `non-deterministic`, `willexit`, `independent` | Ported compiler loops need explicit annotations |

## Non-gaps With Large Translation Cost

| Topic | Why It Is Not A Gap | Porting Cost |
|---|---|---|
| No garbage collector | Stark intentionally uses ownership, move, drop, and borrow checking | Compiler IR graphs use the resolved OQ-16 model: arena/table storage with typed handles, first-class fact tables, and fact-transfer validation. Direct C# object graph translation is rejected. |
| No exceptions | Stark intentionally uses values for recoverable errors | Requires broad error-value conventions and possible `trap` policy for invariants |
| Explicit storage classes | Stark locals require `stack`, `heap`, `register`, `static`, or future `arena` | Mechanical rewrite burden for every C# local |
| No trait objects | Stark traits/doctrines are compile-time contracts | Compiler abstractions should prefer closed-world generic functions/modules over runtime dispatch |
