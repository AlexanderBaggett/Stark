tables in the companion documents in this folder.

companion document's checklist or `Work Items` section, mark the roadmap item
done only when that linked low-level list is complete. Use `[~]` here when some
linked low-level work has landed but the detailed list still has open items.

- [ ] Add bootstrap staging around the existing C# host, Stage1 Stark compiler, and Stage2 Stark compiler. The first source→codegen thread now exists end to end: `LowerReturnIntToLlvm` (`selfhost/Compiler/Mir.stark`) lexes a trivial `return <int>` source with the self-hosted lexer (`Compiler.Lexing.Lex`), finds the first `IntegerLiteral` token, parses its value from the source span, builds MIR (`const`+`return`), and emits the LLVM `@main` function — verified to produce `define i64 @main() { … ret i64 %v1 }` and to reject source with no literal. The thread also handles arithmetic expressions — `LowerReturnExprToLlvm` lexes `return <int> (<+|-|*> <int>)*` and lowers it as a sum of products (`term (('+'|'-') term)*` where `term` is `int ('*' int)*`) — a two-tier left-associative fold giving real operator precedence — the multiplicative tier (`*`→`mul`, `/`→`sdiv`, `%`→`srem`) binds tighter than `+`/`-`, so `2 + 3 * 4` lowers as `2 + (3 * 4)` and `2 + 12 / 3` as `2 + (12 / 3)`. A primary can also be an identifier — a function parameter resolved through a real symbol table (`ParamName`/`BuildParamTable`/`ParamIndexOf`, comparing source-span bytes): the distinct identifiers become the function's parameters in first-appearance order, so `return x + y` → `define i64 @main(i64 %p0, i64 %p1) { … add i64 %p0, %p1 … }`, a reused name maps to the same `%pK` (`return x * x` → `mul i64 %p0, %p0`, one parameter), and precedence composes (`return x + y * x` → `x + (y * x)`). The `return` keyword lexes as its own token, so it is never mistaken for a parameter; literal-only programs declare no parameters (`@main()`). Multi-statement programs with local variables also lower: `LowerProgramToLlvm` compiles `(var <name> = <expr>;)* return <expr>`, binding each local to its expression's MIR value in a `LocalBinding` symbol table; a later reference resolves (locals before params) to the bound value and is reused rather than recomputed — `var x = 2 + 3; return x * x` → `x = %v3` (the add), reused as `mul %v3, %v3`. Multiple declarations work and earlier locals are visible to later ones: `var x = 4; var y = x * x; return y + x` → `y = mul %v1,%v1`, `ret add %v2,%v1`. The expression fold is shared (`FoldExpr` over a start cursor), so it serves both the single-`return` and the `var`+`return` forms. A single comparison binds below `+`/`-` as the lowest tier: `return x < y` lowers to a signed `icmp` whose `i1` result is zero-extended (`MirOp.ZExt`) to `i64` (1 or 0), and `return x + 1 < y` parses as `(x + 1) < y` — a first taste of control-flow-shaped lowering without yet needing multi-block emission. Full multi-block branching control flow emits too: `EmitLlvmDiamond` composes `EmitLlvmLabeledBlock` into a diamond CFG — an entry block ending in a conditional branch to then/else blocks that both jump to a merge block carrying a phi — verified by a `max(x, y)` function (`%v3 = icmp slt …; br i1 …; … b4: %v4 = phi i64 [ %p1, %b2 ], [ %p0, %b3 ]; ret %v4`) whose emitted IR compiles to a real object via `clang -c`. That diamond is now driven from source: `LowerIfToLlvm` lexes `if <a> <cmp> <b> <then> else <else>` (single-primary operands), lowers the comparison and the then/else values, builds the diamond MIR, and emits the branching `@main` — verified by `if x < y x else y` → the cond-branch + phi function. The then/else arms can be full expressions computed in their own blocks: `if x < y x + 1 else y - 1` lowers so the then block computes `x + 1`, the else block computes `y - 1`, and the merge phi selects (its emitted IR compiles to an object via `clang -c`). So control flow goes source→branching-LLVM end to end (single-primary comparison operands; nested branches and `else if` chains remain). Loops also lower from source: `LowerCountingLoopToLlvm` lexes `var <i> = <init>; while <i> <cmp> <bound> { <i> = <i> <op> <step> } return <i>` and builds the four-block loop CFG — preheader constants, an induction-variable `MirOp.Phi` (`[ init, %preheader ], [ <i><op><step>, %body ]`, the body update forward-referenced into the phi), the comparison guard (`<` or `>` via `LowerComparison`), the body update (`+`/`-`/`*` via `LowerBinOp`) branching back to the header, and the exit returning the loop variable. The loop variable is single-assignment SSA — its source-level mutation (`i = i + 1`) becomes the phi's back-edge incoming, not a store. Verified for `var i = 0; while i < 10 { i = i + 1 } return i` → the four-block loop whose emitted IR compiles via `clang -c` (568-byte object) AND, linked against a C driver, **executes and returns 10** — the source-level loop genuinely counts 0→10. Multi-function modules with cross-function calls also compile: `LowerModuleToLlvm` lexes `(fn <name>() { return <body> })+`, builds a function-name→id table, lowers each body (an arithmetic expression, or a call `<name>()` resolved by name to another function's id), and emits the module — `fn helper() { return 7 } fn main() { return helper() }` → `@f1` (returns 7) and `@f2` (`%v2 = call i64 @f1()`), whose IR compiles to an object via `clang -c`. ## Compiler Bugs Found During Self-Host Work

Host-compiler defects discovered while building the self-hosting stdlib/IR, with
the workaround in place until fixed.

- [ ] `lower-mir` crashes (STK9999, `LowerSwitchCore`: "Accepted switch shape
      could not be lowered by native, partitioned text, or guarded switch
      lowering") on a `switch` over a two-variant enum (e.g. `MemoryStatus`)
      whose case bodies are all empty — i.e. a switch used purely to discard a
      result. Type-check accepts it; MIR lowering cannot emit it. Workaround:
      use `switch (x) { default: }` instead of empty per-variant case bodies.
      `LowerSwitchCore` in `src/Compiler` should treat an all-empty-body
      accepted switch as a no-op (or the checker should reject it with a real
      diagnostic). Found in `System.Collections.Arena.Remove`.
- [ ] `lower-mir` cannot resolve the generic drop of a `List<T>` field when a
      *consumer* package drops a value of a type defined in a *different*
      (non-stdlib) library that owns that `List<T>` (STK9999,
      `MidLevelIrLowering.FunctionMirBuilder` ~5913: "Member call 'Clear' could
      not be resolved for receiver type 'System.Collections.List<...>'"). The
      synthesized field drop's `List<...>.Clear`/`.drop` monomorphization is not
      exported from the owning library, so the consumer's drop synthesis fails.
      It reproduces for *any* `T` (incl. `u32`) and for `Arena<T>`/`SideTable<T>`
      fields; it does NOT affect stdlib-owned types (e.g. dropping
      `System.Collections.Arena<u32>` across packages works) or `dynamic T`
      fields (whose drop is intrinsic). Workaround: library types that cross a
      package boundary store owned tables in `dynamic` columns (as
      `Compiler.Lexing.TokenStream` and `System.Toml` do), not `List<T>`/
      `Arena<T>`. Real fix: export/emit the transitive drop-glue monomorphization
      for a library type's generic-container fields so consumers can synthesize
      its drop. This is a self-host priority — it currently bars `List<T>`/arena
      fields in any compiler-port type a test or driver drops. Found building
      `Compiler.Parsing.CompilationUnitHeader`.
