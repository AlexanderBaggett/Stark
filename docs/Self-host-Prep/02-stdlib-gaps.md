# Phase 2 - Standard Library Gap Analysis

The self-hosted compiler needs a standard library that can replace the .NET BCL
surface used by the host compiler. This audit walks the current `System.*`
modules and the host compiler's BCL usage.

## Gap Table

| ID | Stdlib Capability | Current Stark Surface | Host Compiler Need | Severity |
|---|---|---|---|---|
| S01 | Shared `Option<T>` / `Result<T,E>` conventions | `System.Option<T>` and `System.Result<T,E>` exist as root aliases backed by ordinary `[Ok]`/`[Err]` enums in `System.Core`; module-specific result/status enums also exist (`System.IO.IOResult<T>`, `System.Memory.MemoryResult<T>`, `System.Text.TextResult<T>`) | Migrate compiler-port APIs so nullable refs and `Try*` out patterns use `Option<T>`, while recoverable failures use `Result<T,E>` or domain result/status enums | migration blocker |
| S02 | Text builder and formatted output | `System.Text.OwnedAscii`, `OwnedUnicode`, parse/format helpers, conversions | `StringBuilder`, invariant interpolation, LLVM/MIR/SSA rendering, diagnostics, JSON/TOML emitting | blocker |
| S03 | Text escaping, literal decoding, and golden text support | Source language now has exact-preserving `raw"..."`, `raw"""..."""`, and `$raw` literals; `System.Text` has allocation-aware `TextBuildResult<T>` helpers for Stark string-literal escaping, ordinary/raw string literal decoding, and character literal decoding | Literal encode/decode coverage is landed; remaining golden/snapshot file machinery is tracked under S18 and broader compiler text rendering under S02 | closed for literal encode/decode |
| S04 | Regex or structured pattern matching helper | None found in stdlib; host uses `Regex` in project driver/tests | TOML-ish substitutions, test assertions, diagnostic/source matching | workaround-exists |
| S05 | Compiler integer fact helpers capped at `i1024`/`u1024` | Fixed integer widths through `i1024`/`u1024`; `System.Compiler.IntegerFacts` provides bounded helper types and functions; OQ-07 rejects public BigInt/arbitrary precision for self-hosting | Replace the host's `BigInteger` convenience with bounded compiler-internal helpers for literal/range endpoints, enum tags, SSA facts, known-bit masks, and compile-time folding; overflow or values outside `i1024`/`u1024` are diagnostics | closed |
| S06 | Compiler-grade collections | `List<T>`, `Stack<T>`, `Queue<T>`, `LinkedList<T>`, `Dictionary<K,V>`, `HashSet<T>`, `Lookup<T>`, allocation-free comparator-based `SortBy<T>`, and direct `Ord`-based `Sort<T>` documented; `Dictionary<K,V>` and `HashSet<T>` now have scalar fast paths, compiler-known `ascii`/`unicode` key contracts, explicit static `Hash`/`Equals` support for non-primitive keys, compile-time key-contract diagnostics, allocation-free borrowed lookup wrappers for owned text-key dictionaries/sets through `System.Text`, and borrowed `ascii` lookup through `System.Text.Interning` compiler interners | Blessed OQ-08/doc `19` model still needs ordered maps/sets and explicit deterministic package/diagnostic ordering | blocker |
| S07 | Symbol interning | `System.Text.Interning` provides ASCII-backed interners and nominal ID wrappers for symbols, modules, packages, types, fields, members, and artifact keys, with insertion-order reverse lookup | Port compiler symbol tables so front-end/package text is interned once and later compiler phases use distinct compact IDs in hot paths | blocker |
| S08 | Sorting/searching helpers | `System.Collections.SortBy<T>` provides an in-place deterministic slice sort with an explicit inline `Ordering` comparator; `System.Collections.Sort<T>` provides the same in-place sort through `T: Ord` with direct static `Compare` calls after monomorphization; broader ordered collection/search APIs remain future work | Deterministic pass ordering, package image ordering, diagnostics, tool args | workaround-exists |
| S09 | File reading and whole-file helpers | `System.IO.File` supports owned handles, read/write byte slices, whole-file text/byte read and write helpers, atomic whole-file text/byte replacement helpers, line-oriented text reading, seek, delete/move/exists, and error-preserving open results for platform failures | Read `.stark`, TOML, JSON, package images, source snippets; write temp files/artifacts | blocker until richer UTF decoding policy closes |
| S10 | Filesystem metadata/temp/walk | `System.FileSystem` supports create/delete/open directory, read entries, exists/isfile/isdir/move, cross-platform metadata, platform-backed temp-directory creation through `System.IO.Path` temp candidates, recursive walk, streaming glob traversal, symlink read/create policy, and richer IO errors | Temp dirs, recursive source discovery, metadata for incremental builds, permissions | blocker until cross-platform walk parity closes |
| S11 | Path manipulation | `System.IO.Path` supports separator/current-directory/temp-directory helpers, glob matching, two/three/four-part joins, separator and lexical normalization, full-path construction, extension/base/dir/root facts, rooted/absolute/relative checks, extension rewriting, and explicit temp name/path candidate helpers | Broader platform-root policy beyond drive/root-separator facts | workaround-exists |
| S12 | Process spawn/capture/env/argv | `System.Process` routes through the `System.Runtime.Platform` dispatch layer and exposes `CurrentId`, `Exit`, command construction, `RunCapture`, `RunCaptureWithInput`, timeout-aware capture, stdin/stdout/stderr capture, exit-code capture, live environment reads, environment mutation for spawned children, current-directory get/set, and argv/argc reads on the Linux (fork/execvp) and macOS (posix_spawnp) backends | `clang`, linker, archiver, `pkg-config`, test executable runs, stdin/stdout/stderr capture, env vars, CLI args | blocker until the Windows process backend and executable-permission helpers land |
| S13 | `System.Toml` parser/emitter | No public TOML module found; OQ-10 resolves to a reusable `System.Toml` library rather than a manifest-only parser | Parse and emit TOML for `Stark.toml`, `Stark.solution.toml`, `Stark.user.toml`, user config, tests, and tools; project driver performs typed manifest decoding on top of parsed TOML values | blocker |
| S14 | Package inspection JSON/text support | `System.Json` provides a public document reader (flat node table, escape and surrogate decoding, member/child navigation, i64 access) and a compact escaping writer; the host-compiler test harness consumes it for the test protocol | Deterministic JSON/text output for `stark inspect-pkg` and package-image golden tests; normal dependency loading uses the binary codec tracked under T07/doc `20` | reader/writer landed; `stark inspect-pkg` integration and deterministic export remain |
| S15 | Time/stopwatch | No broad time module found | targeted debug timings, regression/benchmark harness | nice-to-have for self-host; not on the cutover path |
| S16 | Threading coordination | `System.Threading` exposes no-payload and explicit payload thread start/join/detach, sleep/yield, seq-cst atomic types, `System.Threading.Synchronized<T>` / `Locked<T>` guarded shared state, and MPSC `Channel<T>` / `Sender<T>` / `Receiver<T>` handles; platform wait/wake hooks remain internal | Synchronous self-hosting needs no concurrency. Future parallel build/test uses the doc `22` payload/thread coordination surface | workaround-exists for single-threaded v1; core coordination surface implemented; broader tests/docs/integration remain tracked in doc `22` |
| S17 | Arena/table IR storage and fact tables | `System.Memory.Allocator` default identity and internal allocation; `arena` reserved, not executable local storage; OQ-16/doc `24` resolves the compiler model as arena/table storage with typed handles plus fact tables | Public allocator/table support for compiler-owned arenas, bulk release, typed-handle dense storage, fact side tables, and validation-friendly builders; `Rc`/`Arc` is not the default IR model | blocker |
| S18 | Testing/golden/snapshot support | `System.Testing` has finite-law bool/equality, `NotEqual`, text contains/starts/ends/count occurrences, range, slice/List shape assertions, root `Option`/`Result` shape predicates, structured diagnostic predicates, compile-time type assertion predicates, process output assertions, run-and-match helpers with optional stdin, process timeout helpers, `RunFact`/`SkipFact`, finite-law `ExitCode`, `TempDirectory` fixture helpers, and snapshot/golden text helpers with explicit verify/update mode, normalized line-ending comparison, first-difference facts, stable formatting, plus build-time generated explicit `[Fact]` / `[Theory]` runners with inline data, typed indexed `[MemberData]` providers, target-triple platform gates, and serial collection grouping through `stark test` | xUnit parity: rich diagnostic rendering/adapters and port-specific assertion adapters | blocker for TDD-first port |

## Stdlib Priority For Self-hosting

1. S18 test support, because tests port first.
2. S12 process/env/argv and S09-S11 file/path/filesystem, because tests and build driver need host compiler/tool execution.
3. S01/S02/S06/S07/S13/S14 plus T07/doc `20`, because the compiler core cannot be ported without result values, text builders, generic collections, typed compiler interners, `System.Toml`, binary package-image loading, and deterministic package-image inspection/export. S05 is closed by `System.Compiler.IntegerFacts`.
4. S17 arena/table IR storage and fact tables, because large compiler IR graphs and backend facts need the decided typed-handle/fact-preserving model before mass porting.
5. S16/S15/S04 as parity and maintainability work. S16's core pieces are implemented: explicit payload thread starts, `Synchronized<T>`, and channels; broader tests/docs/integration remain if parallel build/test execution is chosen before bootstrap.
